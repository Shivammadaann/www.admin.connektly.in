CONNEKTLY ADMIN PANEL - WORKINGS AND FEATURES
Generated from the codebase in www.admin.connektly.in on 2026-05-05.

1. PRODUCT SUMMARY

The Admin Panel is the Connektly owner control plane. It is built for owner/admin operators to monitor and manage all customer workspaces, users, billing, credits, webhooks, integrations, server health, admin users, and internal platform settings.

The application has two main parts:
- React/Vite frontend in src/.
- Express/Supabase admin API in server.ts.

The frontend authenticates with Supabase Auth, then calls the admin API with the Supabase access token as a bearer token. The backend verifies the token, checks admin access, uses the Supabase service role key for privileged reads/writes, and returns normalized admin-specific responses.

4. LOGIN AND ACCESS FLOW

Login:
- /login renders the owner sign-in screen.
- Users sign in with Supabase email/password auth.
- Cloudflare Turnstile is supported through TurnstileWidget and a captcha token is passed to Supabase signInWithPassword when a Turnstile site key is available.
- After successful login, the app redirects authenticated users to /dashboard.

Session handling:
- src/lib/supabase.ts creates a Supabase browser client.
- getCachedSession caches the current Supabase session and avoids repeated session fetches.
- App.tsx listens to Supabase auth state changes and updates the active session.

Admin verification:
- ProtectedAdmin calls adminApi.me().
- The backend requireAdmin middleware verifies the bearer token using the Supabase anon client.
- The backend then resolves admin access from owner_admin_users, primary owner email, or legacy env allowlists.
- If the user is not allowed, the API returns 403 and the UI shows "Owner access blocked".

Permission model:
- Primary owner has all permissions and can manage dashboard admins.
- Non-owner admins only see nav items for permissions assigned to them.
- Disabled admin users are blocked.
- The primary owner cannot be edited or removed from the dashboard admin list.

Admin permission keys:
- command_center
- organizations
- global_users
- platform_settings
- payments
- logs_monitoring
- global_integrations
- webhooks
- server_status
- security_audit

6. LIVE EVENTS AND REALTIME WORKING

Frontend:
- LiveEventsProvider opens /api/admin/live as an authenticated server-sent event stream.
- The provider stores the latest 200 events, tracks connection status, and increments unread count.
- If the stream disconnects, it tries to reconnect after 3.5 seconds.
- The header bell shows unread event count and a dropdown of recent events.

Backend:
- /api/admin/live starts the realtime bridge, opens an SSE connection, sends a hello event, replays the latest 10 buffered events, and sends heartbeat frames every 25 seconds.
- startRealtimeBridge subscribes to Supabase realtime postgres_changes for key tables.
- Each database change is mapped into a normalized live event with title, severity, status, source, table, user ID, and raw payload.
- recordAdminAudit also pushes live admin action events immediately.

Realtime tables watched by server.ts:
- app_profiles
- meta_channels
- instagram_channels
- messenger_channels
- conversation_threads
- conversation_messages
- call_logs
- call_sessions
- meta_lead_capture_events
- whatsapp_payment_configuration_events
- credit_ledger
- email_campaigns
- user_notifications
- owner_admin_profiles

The migration also adds these plus owner_admin_audit_events, owner_admin_users, and user_platform_settings to the Supabase realtime publication when available.

19. SUPABASE MIGRATION / DATABASE SUPPORT

Migration file:
- supabase/admin_dashboard.sql

Creates:
- owner_admin_audit_events: Persisted admin action log.
- owner_admin_profiles: Owner/admin profile settings.
- owner_admin_users: Dashboard admin access rows, roles, statuses, permissions, and invite metadata.
- user_platform_settings: Runtime platform settings by section.
- owner-admin-profile-pictures storage bucket.

Security:
- RLS is enabled on admin tables.
- Policies deny direct client access with using(false) and with check(false).
- The dashboard server uses the service role key for admin table reads/writes.

Seed behavior:
- Inserts/updates the primary owner row for admin@connektly.in by default.
- Links primary owner auth_user_id to auth.users when matching email exists.

RPCs:
- get_user_platform_settings(p_org_id uuid default null):
  - Returns public platform settings for the main app.
  - Excludes API keys.
  - Applies organization-specific feature flag and rate limit overrides.
- get_admin_user_login_activity(p_user_id uuid, p_limit integer default 100):
  - Reads auth.audit_log_entries through a security-definer function.
  - Extracts event type, IP address, user agent, device, and raw payload.

Realtime:
- Adds admin and app tables to supabase_realtime publication when publication exists.

- Organization actions.
- User profile update.
- User credit adjustment.
- User notice send.
- User ban/unban.

How audit works:
- recordAdminAudit pushes a live owner-dashboard event immediately.
- It also tries to insert into owner_admin_audit_events.
- If the audit table is missing, the live event still works and the persisted insert is silently skipped.

Safety checks:
- Protected routes require a valid Supabase session and admin API verification.
- Admin APIs require bearer token.
- Feature endpoints require specific permissions.
- Admin-user management requires primary owner.
- Profile photo type and size are validated client-side and parsed server-side.
- Password changes require minimum length.
- Credit adjustments require positive amount.
- User notices require title and body.
- Organization delete, WABA disconnect, and webhook unsubscribe ask for browser confirmation.
- Secrets are masked in platform settings responses.


22. CURRENT IMPLEMENTATION NOTES

- The admin panel is not only a read-only dashboard. It performs privileged writes through the service-role backend.
- Most list views are client-triggered refresh screens rather than polling pages.
- Live events stream through SSE and are backed by the server process memory buffer plus Supabase realtime.
- If the server restarts, live event buffer is reset, but persisted audit rows remain if the migration was applied.
- Some API responses tolerate missing optional tables by returning empty rows and warnings.
- User Platform Settings continue to return defaults if the settings table has not been applied, but saving requires the migration.
- Logs & Monitoring is the currently routed home for webhooks, server status, and audit views.
- The header search input is visual only in AdminLayout; it is not wired to global search behavior in the current code.
- Turnstile support exists on login, with local/production site key handling in src/lib/config.ts.
- CLIENT_API_BASE_URL is optional, but without it the client API health and generated webhook URL references are limited.
